## 项目是什么

**Hermes 的 Agent/配置/Skills + 适配 Hermes 的 Web 工作台 + U 盘便携外壳。**

目标：一次成功，多次复用；一张已验证能力卡片对应一项有证据、适用范围明确的方法。
Hermes 负责规划和工具执行；工作台负责输入、真实状态、审批与证据展示；外壳负责运行时、
目录迁移、服务和程序更新。不另建 DAG/工作流执行引擎，不承诺通用业务回滚。
打印机只是可选案例，首个试点使用测试文件整理。远程 API 优先，不集成本地模型 Runtime。

## 下一步顺序

1. 本机 Hermes 核对统一分支和剩余审查问题，记录最新基线 SHA。
2. 下发一个小批次，由公司 Hermes 独占开发并回交；本机审查后追加修复或批准下一批。
3. 完成学习产出、验证记录、配置/更新入口及 UI 收尾；真实状态未知时明确显示未知。
4. 满足 [P2 交付门槛](p2/ACCEPTANCE.md) 后生成一个集中测试包、可信哈希、安装/恢复说明。
5. 用户有设备后分别完成 P0/P2 集中验收；不要反复要求零散补丁测试。
6. P3 用独立配置开展低风险方法复验；真正驱动/AD 等操作单独授权。

## 已确认决策与授权边界

- 自有工作台为主；原 Web/CLI/TUI 为备用，保留原启动器。
- 首次安装基线和后续更新分开；内核复用经核实的上游更新器，外壳独立安装/恢复，
  Runtime 按锁校验。声明版本相同不代表提交/协议相同。
- 更新自动检查、通知；安装须确认。兼容性未知不能静默应用；不修改清单来伪造发布资格。
- Agent/Skill 内容由 Hermes 在用户指定的独立实例配置；提示词不是权限沙箱。
- 2026-09-20 起开发协作采用本机负责人 + 公司开发者。负责人批准代码交付，
  不等于批准管理员操作、模型费用、安装、发布、私人数据传输或真实业务执行。
- 方案调整、自动通信、公司数据使用和代码推送范围须得到对应授权；2026-09-21 用户已授权
  整合、推送及删除多余交接分支。本轮不配置 Hermes 实例、不自动下发消息、不发布包。
- 旧 ADR 的有效边界并入 AI 指南；历史全文保留于 Git，不继续维护重复进度文档。
