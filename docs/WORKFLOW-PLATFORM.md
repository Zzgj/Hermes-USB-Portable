# Hermes 工作台：配置、Skill 与跨电脑复用

2026-09-09 用户确认：项目由 Hermes Agent 与配置/Skills、适配 Hermes 的 Web UI、U 盘便携外壳组成。
打印机安装只是案例。通过 Hermes 将已验证的方法沉淀为 Skill/流程文档及必要脚本，在其他电脑重新执行。
不修改内核是默认边界；接口不足先核实并记录，必要扩展单独评估。

| 对象 | 保存内容 |
|---|---|
| Skill | 方法、适用条件、工具使用说明、验证范围 |
| Agent 配置 | 角色提示词、选用模型/Skill/工具、允许范围；优先使用上游配置机制 |
| 流程方法 | 版本、输入、条件、步骤、验证和恢复说明，存于 Skill 或文档，不要求自有 DSL |
| 本次执行记录 | Hermes 实际会话/任务标识、方法版本、本机参数、审批与脱敏证据 |

工作流是完成工作的步骤组织方式，不等于要自行开发一个执行引擎。
Hermes 负责规划和调用工具，工作台展示实际事件并适配已有审批；步骤缺失时显示未知。
现有模拟状态引擎仅为 UI 测试夹具，不再扩展为生产调度器。

## 谁来配置与开发

用户已确认把工作流 Agent 的配置与 Skill 内容建设交给 Hermes 自身完成：先给方案、备份配置，
再在明确指定的实例中执行；不修改内核、不自动安装第三方 Skill/MCP、不把草稿自动标为验证通过。
Codex 继续负责工作台、便携外壳与必要接口适配，不在开发机重复搭建同一套 Agent。
用户批准配置目标、安装与权限并核对实机结果。此分工不代表已经开始任何配置操作。
优先验证一个 Agent 的低风险闭环，再决定是否需要多个专用 Agent。
用户已确认：先使用独立测试配置/实例，以测试文件整理作为首个场景，通过验证后再迁移到
常用配置。具体实例路径、测试文件范围和迁移变更在执行前核对，不使用私人文件作为默认试点。

## 从 A 电脑到 B 电脑

1. 在 A 完成工作，记录操作、前置条件、结果和适用范围。
2. 提取通用方法，将机器相关信息参数化，生成草稿。
3. 人工审核来源、敏感信息、权限范围与恢复策略，发布带版本的定义。
4. 在 B 重新绑定本机输入、探测条件与依赖，生成本次计划。
5. 针对本次目标重新确认权限；A 的批准不能继承到 B。
6. 执行、验证并保存新记录。不匹配应停止、分支或请求帮助，不能假报成功。

打印机可能需要系统、网络、驱动检查；文档归档可能需要选文件、提取、分类、确认输出和写入。
平台不得把打印机的检查顺序套用给其他工作流，也不能硬编码 A 的 IP、路径或凭据。

## 已验证能力卡片与学习闭环

**一张已验证卡片 = 一项有成功证据、适用范围明确、可以重新调用的方法。**
卡片只描述任务目标、输入、Skill/Bundle 引用、版本/内容指纹、环境依赖、验证条件与历史证据。
不把每个命令/节点编码成工作台自己的执行引擎，也不把 Toolsets 声明当成已经获得权限。

推荐入口为“我的能力”“执行记录”“整理为可复用技能”，聊天是执行与解释的基础界面。
过程是：真实任务完成并验证 → 主动发起 `/learn` → Hermes 生成草稿 → 审核 → 试跑该 Skill →
保存证据并形成已验证卡片 → 换环境时重新检查、授权和验证。
原操作成功不能替代生成 Skill 的复验；版本、Bundle 成员或适用环境变化时提示重新验证，
保留历史证据但不将其当成当前版本已通过。失败经验进入排错参考，不自动成为成功卡片。

已核对开发机 `cli_commands_mixin.py` 与 `tui_gateway/methods_tools.py`：`/learn` 构造指导提示，
交给 Agent 通过已有工具整理 Skill，不是录制器或确定性回放引擎。适配仍须验证目标内核契约。
官方参考：[Skills 与 /learn](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills/)。
Bundle 是多个 Skills 的组合加载入口，不保证依次执行；具体顺序、失败处理和业务验证由方法约束。

方法优先使用适合的 API/CLI，Browser/Computer Use 按需补充；不保证 GUI 自动化始终可用。
Obsidian 为可选知识沉淀位置，不作为卡片执行必需条件，不默认归档完整私人会话。

## 安全边界

- 模型生成的流程不是可信可执行代码；进入系统执行前必须验证与审核。
- 凭据用受控引用绑定，不放入可分享的定义或证据。个人信息按需脱敏。
- 审批绑定执行实例、步骤和具体计划；计划变化使旧审批失效。
- 取消不代表撤销副作用。只有实际执行并验证恢复后才能标记回滚成功；不支持时提供人工恢复说明。
- 验证记录注明系统、版本、时间和结果；超出范围时重新检查，不能以 trusted 标签保证成功。

## 阶段归属

P0 保留运行、迁移、更新和数据保护基线；已通过的证据不作废，最终验收仍待完成。
P1 盘点并适配配置、凭据和知识边界，不重写 provider/profile 系统。
P2 建立聊天、会话、实际任务状态、审批、最小配置选择与服务管理 UI。模拟不代表真实执行或授权。
P3 做 Hermes 配置集成、Skill 草稿与审核、按需 Skill/MCP 管理及两个不同场景的跨电脑验证。
打印机可选，专用驱动仓库和业务 UI 按实际需求后置，不是平台先决条件。
外壳安装恢复仍由本项目负责；业务副作用的恢复由具体 Skill/工具支持并实测，不能混为一谈。

P2 视觉仍以 Stitch 为基准。用户确认整体方向，但配色、字体、间距和组件样式仍有偏差，
视觉还原尚未验收。P0 实机验收不因 P2 开发而视为通过。
